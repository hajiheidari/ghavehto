# Initial sign-in activation gate

Internal OTP → encrypted identity → opaque session → scoped API behavior has real disposable PostgreSQL/HTTP tests. That evidence does not prove actual SMS arrival, end-user sign-in, secure client persistence, physical-device behavior or publication readiness.

The founder's explicit restriction remains: «SMS واقعی بدون ارائه‌دهنده و مجوز ارسال فعال نشود.» No real adapter, account, paid service, fixed code, demo token or bypass route has been enabled.

## Required external input

1. Name of the existing/approved SMS provider and whether an account already exists. No account creation or purchase is implied.
2. Approved sender/template identity and provider API contract. The adapter must support the reviewed code format, cancellation/deadlines and non-sensitive error handling.
3. Provider credentials supplied through a secure configuration mechanism, never chat, Git, test logs or a shared artifact.
4. A separately approved test destination in secure configuration and an explicit small real-send budget/authorization. No outreach or arbitrary consumer sends.

Only the provider name is needed in chat to identify the next integration. Do not paste API keys, passwords, real OTPs or private recipient data into the conversation.

## Work after selection

- Implement and review that specific adapter; preserve disabled defaults, persisted budgets, request deadlines and safe error responses.
- Provision separate OTP HMAC, stable private lookup and authenticated encryption keys in secure runtime configuration; define rotation/recovery.
- Compose initial request/verification transport, genuine web HttpOnly/Secure/SameSite cookie plus CSRF handling and mobile platform-secure token storage. Never store credentials in localStorage or add a fake successful login.
- Test delivery acceptance separately from observed receipt, then complete the real sign-in/rotation/logout flow on intended devices and networks.
- Finish visual QA, publisher/region feasibility and remaining security/operational gates before any separately approved public deployment/store action.

M1 remains open until its applicable acceptance gates pass. M2 directory/provenance/claims follows the milestone plan. Core consumer/café features remain free; stamps, spendable stars and non-spendable tier journals stay independent and deferred to M3.
