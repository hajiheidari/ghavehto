# Product delivery while SMS activation is deferred

The founder deferred SMS.ir activation until the site is operational and the panel and eNamad prerequisites can be reviewed. Treat those prerequisites as a project decision, not a verified statement of provider policy. Keep the initial login routes unregistered in standard startup. No vendor application, deployment, SMS or expense is authorized by this sequencing.

| Increment | Deliverable | Verification before rollout |
| --- | --- | --- |
| Directory browse | Public SSR search over reviewed branch snapshots; distinct empty, unavailable and no-match states | PostgreSQL publication/withdrawal isolation, API input limits, RTL SSR |
| Directory stewardship | Staff review, permitted field lineage, re-review dates, correction and takedown queue; separate original and normalized values | Audit every decision; revoked rights immediately remove visibility; no third-party bulk import |
| Claims and access | Evidence intake, reviewer decisions and branch-scoped staff; never equate listing, claim, verification and active partner | Tests for cross-tenant reads, evidence privacy, duplicate claims and revocation; real-user entry waits for approved identity activation |
| Loyalty | Versioned café stamp program, independent platform star and membership tier journals, one-use QR and stock reservation | Concurrent replay, overspend and reversal tests across independent ledgers; tier points cannot be spent |
| Experiences and referrals | Eligibility windows, budgets, attribution and confirmed-visit rules | Expiry, duplicate claims, per-café budgets and attribution tests |
| Operations | Review queues, agent pause/retry/approval, CMS revisions and reporting | Audit and idempotency, provider defaults disabled, no outreach or spending by default |
| Release | Private staging, accessibility and device checks, backups and deletion, rollout and rollback plan | Separate approvals for public deployment, provider activation, sending and store submissions |

Consumer and café essentials remain free. Directory records are public only after an explicit review; a listing never grants ownership, membership or eligibility for rewards. The first directory read publishes names and locality only. Public business contacts, location, opening hours and photos require their own reviewed provenance and correction controls before exposure.

The snapshot is a moderated projection linked to a real branch and an allowed source for the same café. Tenant edits affect the private profile, not the public snapshot. Withdrawal, denial of the source, or café deactivation hides the snapshot immediately. Future publication tools must write the decision and audit in one transaction and restrict access to evidence.
